# QuickShed v0.6.0 Release Readiness Audit

Date: 2026-06-21
Scope: local repository, live Vercel deployment, documentation, release process, and GitHub repository settings.
Mode: review plus approved local remediation batch.

## Executive Verdict

Status: BLOCKED.

QuickShed builds successfully and the live site renders on desktop, mobile, and Arabic RTL routes. However, the project is not ready for an official v0.6.0 launch because public release archives are still served from the current Vercel production deployment and include internal workspace paths, including `.env` filenames. The local release branch now contains fixes for the public archive source, XSS sinks, password randomness, CSP-incompatible math evaluation, canonical share URLs, and CI smoke coverage, but production remains blocked until the fixed branch is reviewed, deployed, archive URLs return 404, and secret rotation/history review decisions are recorded.

## Blocking Findings

### CRITICAL-001: Public archives expose internal workspace material

Files:

- `public/quickshed-complete.zip`
- `public/quickshed-complete.tar.gz`
- `public/quickshed-v1.0.0.zip`
- `public/quickshed-v1.0.0.tar.gz`

Evidence:

- The files are tracked by Git and present in `public/`.
- They are downloadable from the live Vercel deployment.
- Archive listings include internal paths such as `my-project/.env`, `my-project/upload/_extract/.env`, `my-project/skills/`, `my-project/upload/`, and nested archives.
- Secret contents were not opened or copied during this audit.

Impact:

This is a release-blocking exposure. Even if the `.env` values are placeholders, the deployed archives contain internal workspace material and must be treated as a potential secret leak until proven otherwise.

Required action:

1. Remove all archives from `public/`.
2. Redeploy immediately and verify all archive URLs return 404.
3. Rotate any secrets that may have existed in packaged `.env` files.
4. Inspect Git history and prior deployments for exposed archives.
5. Add CI guards that fail if `.env`, archives, or internal directories appear under `public/`.

Local remediation status:

- Fixed locally by deleting the four archives from `public/`.
- Added `scripts/check-public-assets.mjs` and wired it into `release:check` and the Playwright GitHub Actions workflow.
- Live production still served the archive URLs with HTTP 200 during the post-fix check, so the public incident remains open until redeploy/removal is verified.

### CRITICAL-002: Markdown-to-HTML tool renders unsanitized user HTML

File: `src/components/tools/MarkdownToHtml.tsx`

Evidence:

- `markdownToHtml()` interpolates user input into HTML strings.
- The result is rendered through `dangerouslySetInnerHTML`.
- Link, image, heading, code, paragraph, and list substitutions do not escape HTML.

Impact:

User-provided Markdown can become active HTML in the QuickShed origin. This contradicts the privacy/security posture and creates a client-side XSS risk.

Required action:

- Replace the ad hoc parser with a vetted Markdown renderer configured to disallow raw HTML, or escape all text and sanitize the generated HTML before rendering.

Local remediation status:

- Fixed locally by escaping Markdown input before conversion and restricting generated link/image URLs to safe schemes.
- Covered by Playwright XSS regression smoke.

### CRITICAL-003: JSON raw view renders highlighted user content through `dangerouslySetInnerHTML`

File: `src/components/tools/JsonFormatter.tsx`

Evidence:

- `highlightJson()` performs regex replacements on JSON text.
- The highlighted output is rendered with `dangerouslySetInnerHTML`.
- JSON strings are not HTML-escaped before insertion.

Impact:

JSON string values can become live DOM in the app origin.

Required action:

- Escape HTML entities before highlighting, or render highlighted tokens as React nodes.

Local remediation status:

- Fixed locally by tokenizing JSON and escaping all non-token and token text before inserting syntax-highlight spans.
- Covered by Playwright XSS regression smoke.

## High Findings

### HIGH-001: Random password generator uses `Math.random()`

File: `src/components/tools/RandomPasswordGenerator.tsx`

Evidence:

- Pronounceable, PIN, and normal password paths use `Math.random()`.

Impact:

This is a security-labeled tool and should not generate passwords or PINs using non-cryptographic randomness.

Required action:

- Use `crypto.getRandomValues()` consistently, following the stronger pattern already present in `PasswordGenerator.tsx`.

### HIGH-002: Share and embed links do not route to tools

Files:

- `src/components/ShareTool.tsx`
- `src/components/ExportShareSection.tsx`
- `src/components/views/ToolView.tsx`
- `src/lib/store.ts`

Evidence:

- Share links are generated as `/?tool=<id>`.
- Store initialization parses locale path routes like `/en/tools/<id>`, not query strings.

Impact:

Copied/shared links open the home page instead of the intended tool.

Required action:

- Generate canonical locale-aware URLs such as `/${locale}/tools/${tool.id}`.

### HIGH-003: Playwright CI is not release-ready

Files:

- `.github/workflows/playwright.yml`
- `playwright.config.ts`
- `test/example.spec.ts`
- `.gitignore`

Evidence:

- The workflow exists locally but is not present on GitHub.
- The test file targets `https://playwright.dev/`, not QuickShed.
- The `test/` directory is ignored by `.gitignore`.
- CI uses `npm ci` while the repo also tracks `bun.lock` and has an untracked `package-lock.json`.

Impact:

The current E2E setup does not validate QuickShed and cannot be trusted as a release gate.

Required action:

- Choose one package manager strategy.
- Add QuickShed smoke tests for `/en`, `/ar`, core tool pages, search, and mobile.
- Configure a local `webServer` or explicit live smoke mode.
- Stop ignoring committed test specs.

### HIGH-004: Math equation solver likely fails under production CSP

Files:

- `src/components/tools/MathEquationSolver.tsx`
- `next.config.ts`

Evidence:

- The solver uses `new Function()`.
- Production CSP omits `unsafe-eval`.

Impact:

Valid expressions can fail in production, and enabling `unsafe-eval` would weaken the CSP.

Required action:

- Replace `new Function()` with a small parser/evaluator or a vetted expression library that does not require eval.

### HIGH-005: Dependency audit currently fails

Evidence:

- `npm audit --omit=dev --audit-level=moderate` reported 20 vulnerabilities.
- Reported families include Next.js, next-intl, Prisma/effect, lodash/lodash-es, js-yaml, PrismJS, uuid, picomatch, and other transitive packages.

Impact:

The project cannot honestly claim active weekly audits or 24-hour critical patch handling while the audit gate is failing and no Dependabot workflow is enabled.

Required action:

- Upgrade dependencies in a controlled PR.
- Separate runtime-impacting vulnerabilities from unused dependencies.
- Add a scheduled audit gate and Dependabot or Renovate.

## Medium Findings

### MEDIUM-001: Version and release identity are inconsistent

Evidence:

- `package.json` says `1.0.0`.
- Settings UI displays `v1.0.0`.
- Public archives are named `v1.0.0`.
- The requested release target is `0.6.0`.

Required action:

- Adopt one semantic version source of truth and generate UI/version/release notes from it.

### MEDIUM-002: Documentation overstates security posture

Evidence:

- README claims "Strict CSP with nonce support" and "CSP compliant".
- Current CSP uses `unsafe-inline` and no nonce.
- Privacy page claims weekly dependency audits and 24-hour critical patching.
- GitHub currently has no security policy and dependency alerts are disabled.

Required action:

- Either implement these controls or revise the wording before promotion.

- Add baseline open-source governance files before public promotion.

## Skills and Guards Selection

Recommended project-specific skills:

- `quickshed-dev-workflow`: primary project workflow for Next.js 16, SSG, hydration, CSP, service worker, and Vercel issues.
- `frontend-testing-debugging`: rendered UI and live deployment checks.
- `source-code-intelligence`: source-level architecture and risk mapping.
- `github-code-review`: repository, PR, and GitHub hygiene audits.
- `spec-kit-sdd`: release planning only, with explicit approval gates before implementation.

Recommended guards:

- Public asset leak guard: fail if `public/` contains `.zip`, `.tar`, `.tar.gz`, `.env`, `upload/`, `skills/`, or nested archives.
- Secret scan: gitleaks or GitHub secret scanning.
- Type and lint gates: `tsc --noEmit`, `npm run lint`.
- Build gate: `npm run build`.
- E2E gate: QuickShed Playwright smoke tests.
- Dependency gate: `npm audit` or better curated advisory scanner.
- GitHub branch protection: require all green checks before merge.
