# QuickShed v0.6.0 Release Checklist

Date: 2026-08-06
Status: local Phase 8 implementation closed; publication gates remain open

## Required Before Tagging

- [x] Public archive URLs return 404 in production.
- [x] Public asset guard is enforced locally and in GitHub Actions.
- [x] GitHub branch protection requires the `test` check.
- [x] Security policy, license, contributing guide, issue templates, PR template, CODEOWNERS, and Dependabot config are present.
- [x] Release identity is set to `0.6.0`.
- [x] README and public privacy/security claims match implemented controls.
- [x] Official repository links point to `https://github.com/Habib1001-m/quickshed`.
- [x] Release check uses the same browser scope as CI.
- [x] Mobile viewport and service-worker-safe navigation smoke coverage exist.
- [x] Dependency audit policy is documented.
- [ ] Owner records secret rotation or no-real-secret decision for the removed public archives.
- [x] Current local `npm run release:check` passes on the working tree after the discovery-remediation review (287 passed, 1 skipped).
- [ ] Final `npm run release:check` passes on a clean checkout or CI run for this change.
- [ ] Final live smoke test passes after the release commit is deployed.

## Release Procedure

1. Confirm the checklist above is complete.
2. Run `npm ci`.
3. Run `npm run release:check`.
4. Push through a pull request and wait for GitHub Actions and Vercel to pass.
5. Verify production archive URLs still return 404.
6. Verify `https://quickshed.vercel.app/en` and `/en/tools/json-formatter` render without console errors.
7. Create tag `v0.6.0`.
8. Draft GitHub release notes from `CHANGELOG.md`.
9. Review release notes with the owner before publishing.
