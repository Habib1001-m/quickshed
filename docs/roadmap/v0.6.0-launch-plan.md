# QuickShed v0.6.0 Official Launch Plan

Date: 2026-06-21
Status: partially implemented locally; production release remains blocked pending redeploy, incident closure, dependency policy, and GitHub governance setup.

## Objective

Prepare QuickShed v0.6.0 for an official public launch with a clean repository, trustworthy security posture, real CI gates, accurate documentation, and promotion-ready product surfaces.

## Phase 0: Incident Containment

Goal: stop the current public artifact exposure before any launch work.

Tasks:

1. Remove all release archives from `public/`.
2. Redeploy and verify these URLs return 404:
   - `/quickshed-complete.zip`
   - `/quickshed-complete.tar.gz`
   - `/quickshed-v1.0.0.zip`
   - `/quickshed-v1.0.0.tar.gz`
3. Rotate any secrets that may have existed in archived `.env` files.
4. Review Git history and Vercel deployment history for exposed archives.
5. Add a public asset leak guard to CI.

Exit criteria:

- No archives are served from the production site.
- Secret rotation decision is recorded.
- CI blocks future public archive leaks.

## Phase 1: Security Hardening

Goal: close release-blocking security bugs.

Tasks:

1. Fix `MarkdownToHtml` unsafe HTML rendering.
2. Fix `JsonFormatter` raw highlighted output rendering.
3. Replace `MathEquationSolver` eval path with a CSP-compatible evaluator.
4. Replace `Math.random()` in `RandomPasswordGenerator`.
5. Run dependency remediation and document any accepted residual risk.

Exit criteria:

- No user-controlled content is rendered through unsafe HTML sinks without escaping/sanitization.
- Password and PIN generation use Web Crypto.
- Production CSP remains compatible with all tools.
- Dependency audit has an approved pass/fail policy.

## Phase 2: Product Correctness

Goal: ensure core user promises work before promotion.

Tasks:

1. Fix canonical share/embed links to use locale-aware tool URLs.
2. Fix or intentionally revise the `Ctrl+K` shortcut behavior.
3. Add Playwright smoke tests for:
   - `/en`
   - `/ar`
   - a representative tool page
   - search or command palette
   - mobile viewport
   - service-worker-safe navigation
4. Verify Arabic RTL and English LTR flows.
5. Verify SEO basics: sitemap, robots, canonical URLs, OG metadata.

Exit criteria:

- Main user flows pass in CI.
- Live smoke test has no console errors or framework overlays.
- Shared links open the intended tool.

## Phase 3: Repository Governance

Goal: make the public GitHub repository look and behave like an official project.

Tasks:

1. Add `LICENSE` or change README license badge if MIT is not intended.
2. Add `SECURITY.md` with vulnerability reporting instructions.
3. Add `CONTRIBUTING.md`.
4. Add `CODEOWNERS`.
5. Add issue templates.
6. Add pull request template.
7. Add release notes template and changelog.
8. Add Dependabot or Renovate.
9. Configure branch protection for `main`.
10. Require CI checks before merge.
11. Decide merge policy and enable delete branch on merge if desired.
12. Add repository topics and accurate description.

Exit criteria:

- GitHub reports a security policy.
- `main` is protected.
- Required checks are configured.
- Repo metadata is complete.

## Phase 4: CI/CD and Release Automation

Goal: make releases repeatable.

Tasks:

1. Choose package manager policy: Bun-first or npm-first.
2. Add CI jobs:
   - install
   - lint
   - typecheck
   - build
   - Playwright smoke
   - dependency audit
   - secret/public asset scan
3. Add release workflow or documented manual release procedure.
4. Add version policy for `0.6.0`.
5. Remove stale `1.0.0` references until a real 1.0 release.

Exit criteria:

- Fresh clone can run the documented workflow.
- CI fails on broken build, tests, audit policy, or public asset leaks.
- Release notes can be generated without manual guesswork.

## Phase 5: Documentation and Marketing Readiness

Goal: align public claims with reality.

Tasks:

1. Update README setup port and package-manager instructions.
2. Correct CSP/security claims.
3. Correct privacy page audit and patch policy claims.
4. Update GitHub links from `github.com/quickshed` to `github.com/Habib1001-m/quickshed`.
5. Add launch positioning:
   - privacy-first browser toolbox
   - bilingual Arabic/English
   - PWA/offline-capable
   - no account/no ads/no tracking
6. Prepare promotion assets after security blockers are closed.

Exit criteria:

- Public docs make only claims backed by implemented controls.
- Launch copy is ready for review.
- No GitHub-facing post, PR body, or public comment is published without owner approval.
